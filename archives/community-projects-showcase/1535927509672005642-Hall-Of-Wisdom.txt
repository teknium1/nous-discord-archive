    _Hall of Wisdom — Deep Dive Analysis_
    
    _What It Is:_
    A *cross-platform Agent OS* built as a TypeScript/pnpm monorepo that orchestrates coding agents (Claude Code, Codex, *Hermes Router*, and others) against your projects. Local-first — never collects your credentials.
    
    _Architecture (19 phases completed):_
    - *Phase 1-2:* Monorepo foundation, adapter SDK
    - *Phase 3:* Mock Agent (deterministic test adapter)
    - *Phase 4:* Hall Runner (local task runner + adapter registry)
    - *Phase 5-5.1:* Hall Core (Fastify HTTP/WebSocket server, stores, orchestration, recovery)
    - *Phase 6:* Hall Web (Next.js dashboard)
    - *Phase 7:* Kanban Board
    - *Phase 8:* Communication Boards
    - *Phase 9-10:* Claude Code & Codex adapters
    - *Phase 11:* Agent capabilities, trust & routing
    - *Phase 12:* Controlled agent comparison (side-by-side)
    - *Phase 13:* Durable SQLite persistence & recovery
    - *Phase 14-15:* CEO planning, approval, delegation, autonomous execution & scheduling
    - *Phase 16:* Codex worktree execution, isolated orchestration, strict mode, restart-safe reconciliation
    - *Phase 17:* Persistent configuration & onboarding (current)
    
    _Hermes Router Adapter — Deep Integration:_
    
    *What's implemented (very thorough):*

[2026-08-09T16:48:05.777000+00:00] irteza080 (id=1536053470149353682)
    1. *Descriptor* (`descriptor.ts`) — Full capability declaration:
       - `project.read`, `project.edit`, `command.execute`, `structured.events`, `cancellation`
       - Streaming: ✅, Cancellation: ✅, Session Resume: ❌ (not supported yet)
       - Tool events: ✅, File editing: ✅, Shell execution: ✅
       - Subagents: ❌, MCP: ❌, ACP: ❌
       - Integration level: `structured_cli` (not just raw CLI, but protocol-based)
       - OS: Windows, macOS, Linux
    
    2. *Detection* (`detection.ts`) — Smart runtime detection:
       - Requires `HALL_HERMES_ROUTER_ROOT` env var pointing to your Hermes Router install
       - Looks for `hermes_agent_runner.py` at that root
       - Runs `python hermes_agent_runner.py detect` with 5s timeout
       - Validates JSONL output against strict Zod schema
       - Returns `unsupported` with "execution not enabled yet" — so it *detects but doesn't execute yet*
    
    3. *Protocol* (`hermes-protocol.ts`) — Full JSONL event protocol:
       - Events: `run.started`, `message.delta`, `tool.started`, `tool.completed`, `file.changed`, `run.completed`, `run.failed`, `run.cancelled`
       - Incremental parser with byte bounds (24MB total, 2000 events, 24KB/line)
       - Sequence validation, terminal event enforcement, UTF-8 strict
       - 14 specific transport error codes
    
    4. *Execution Transport* (`execution-transport.ts`) — Process management:
       - Spawns `python hermes_agent_runner.py run <runId> --prompt "..."` 
       - AbortSignal support for cancellation
       - Streamed JSONL stdout parsing
    
    5. *Adapter* (`hermes-router-adapter.ts`) — Orchestration bridge:
       - Implements `AgentAdapter` interface from SDK
       - Rejects session resumption (`sessionId` not supported)
       - Builds task prompts (8KB max, truncation marker)
       - Returns `HermesRun` handle with async event iteration

[2026-08-09T16:48:07.484000+00:00] irteza080 (id=1536053477308899399)
    6. *Safety* — Multiple layers:
       - NUL character rejection in prompts
       - Byte-bounded line/event/total limits
       - File path safety validation
       - Git worktree registration parsing (NUL-delimited, strict)
       - Cleanup is conservative: never recursive delete, fails closed
    
    _What's Missing / In Progress:_
    - *Execution is disabled* — Detection works but returns "Hall task execution is not enabled yet"
    - *No session resumption* — Must start fresh each time
    - *No MCP/ACP* — Not declared as capabilities
    - *Windows-first* — PowerShell installer, paths tested on Windows
    - *Requires `hermes_agent_runner.py`* — Your Hermes install needs this runner script at the configured root

    🏛️ Hall of Wisdom — Development Update
    
    A lot of work has recently gone into making Hall of Wisdom simpler and easier to use.
    
    🧠 Wisdom Gateway improved
    You can now manage much more of the workflow directly from the Gateway.
    
    A task can move through:
    
    Ask → Plan → Approve → Choose Agent → Prepare → Start → Monitor → Result
    
    You can also see the current step and live progress while the agents are working.
    
    👀 New “Needs Your Attention” area
    Hall now collects important things that require your input in one place, such as:
    
    Plans waiting for approval
    Failed or blocked tasks
    Agent runs that need intervention
    
    So instead of searching around the application, Hall tells you what needs your attention.
    
    🧭 Simpler UI and navigation
    The interface has been cleaned up and grouped into just a few main areas:
    
    Home • Work • Attention • Team • Settings
    
    Advanced information is still available, but technical details are hidden unless you actually need them.
    
    💬 Discuss work directly
    Tasks and plans can now open their own discussion area, making it easier to talk about a task without losing the context.
    
    ✅ Better work results
    After a run finishes, Hall now shows a simple result summary — how many steps completed, what failed, and what may need review.
    
    ⚡ In simple terms
    
    Hall of Wisdom is moving closer to the idea of:
    
    You tell Hall what you want → Hall creates a plan → agents do the work → Hall keeps you updated.
    
    The goal is to make multi-agent workflows usable even for people who don't want to deal with complicated agent configuration.
    
    🧪 The project is still under active development.
    
    Linux testing, bug reports, UI feedback, feature ideas, and contributions are very welcome!
    
    More updates soon 🚀
