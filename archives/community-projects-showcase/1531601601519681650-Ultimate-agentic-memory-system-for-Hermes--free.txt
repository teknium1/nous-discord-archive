    Engraphis: local-first memory for coding agents. Daily updates. Durable context across sessions and repos, bi-temporal history, code-aware recall, MCP, self-hosted WebUI. Apache-2.0, free core. Beats Obsidian in every imaginable metric.
    
    Recall: six-term scoring (retention, semantic, lexical, graph proximity, importance, recency) with visible score breakdowns. Ebbinghaus decay with reinforcement. Deterministic conflict resolution (add/reinforce/supersede), no LLM in the write path. Contradictions invalidate facts instead of overwriting; engraphis_why shows supersession history with word-level diffs.
    
    Local: SQLite + local embeddings (all-MiniLM-L6-v2, 80 MB once). Base lib depends on numpy only. Deterministic offline embedder fallback.
    
    Code-aware: incremental symbol/call/import graph across 11 languages (Python, JS, TS, Go, Rust, Java, C#, C, C++, SQL, Terraform). Tree-sitter with regex fallback. Code↔memory links, path queries, git/PR impact analysis, portable graph exports + git merge driver.
    
    MCP: 29 tools for Claude Code, Cursor, Cline, Zed, Windsurf. Remember, hybrid recall, cited answers or explicit abstention, proactive_context, governance (pin/forget/correct/promote/merge), indexing, impact, privacy receipts.
    
    Security: AES-256 at rest (SQLCipher), loopback default, constant-time bearer token, hostile-input hardening on sync/merge/repo-walk, opt-in auditable LLM extraction with local fallback.
    
    WebUI: 14 tabs, same MemoryService as MCP/library. Supersession diffs, offline force-directed graph, SHA-256 content-free audit receipt chain, full governance ledger, nothing hard-deleted.

    Anyway some thoughts:
    
    I don't get "retention" and "recency" as separate scoring terms. Ebbinghaus retention is already a function of elapsed time plus reinforcement. Scoring both double-weights recency.
    
    "Deterministic offline embedder fallback." A deterministic hash-based embedder produces vectors with no semantic structure. Recall silently degrades to noise while still returning confident-looking score breakdowns and citations. I get it's a fallback, but why does it need a fallback?
    
    The headline says "for Hermes" and nothing in the body is Hermes. Your integration list is Claude Code, Cursor, Cline, Zed, Windsurf. I don't see Hermes integration. 
    
    "nothing hard-deleted" vs. "governance (pin/forget/correct...)" and "privacy receipts." A forget that never deletes is misnamed. A coding-agent memory will ingest .env values, tokens, and keys by accident. If nothing is ever hard-deleted, that secret is permanent and still recoverable from the DB, and AES-256 at rest does not help because your own app holds the key, and anything targetting this will be AI so it won't even confuse or delay.
    
    On branding: "Beats Obsidian in every imaginable metric" is a category error. Obsidian has iOS and Android apps, a WYSIWYG editor, Canvas, and thousands of community plugins.  We're competing with Mem0, which is still big with 24mil in funding.

    Where Engraphis wins compared to Compartment:
    
    Multi-repo project boundaries: First-class workspace → repo → session scopes, rather than Compartment’s flat namespaces plus caller ACLs. Better for isolating work across repos and sessions.
    
    Time-aware fact history: Record-level valid_at and known_at, plus supersession chains, corrections, promotion, and timelines. Compartment has save/discovery dates and temporal relations, but not equivalent bi-temporal memory recall.
    
    Evolving facts without deletion: Engraphis can add, reinforce, relate, or invalidate a claim while retaining its predecessor for “what changed and why?” queries. Compartment deduplicates near-identical records; correction otherwise relies on deletion or shredding.
    
    Code-native memory: Indexes symbols, calls, imports, files, and code-to-memory links. Supports structural search, dependency paths, git-range impact, and PR graph reports. I found no comparable parser, symbol index, or call graph in Compartment. 
    
    Graph-informed retrieval: Engraphis’s entity and code graph is a normal retrieval arm using PPR, not just a manually queried relation store. Compartment’s ranker is vector plus lexical, while relations are queried separately.

[2026-08-02T21:06:06.696000+00:00] jaixii (id=1533581686770765844)
    Grounded answer contract: Returns a cited answer or explicitly abstains below an evidence threshold. Compartment returns ranked records and warnings, not a citation-bound answer or abstention result.
    
    Prompt-context control: Hard token-budget context packets, compact responses, usage accounting, and adaptive fallback to raw history. Better for agents operating under fixed context windows.
    
    Retrieval and model flexibility: Embedders, vector indexes, rerankers, and optional LLM extraction are interface-driven and swappable. Compartment intentionally pins a bundled embedding space, which improves reproducibility but is less flexible for deployments.
    
    Memory lifecycle tooling: Typed working, episodic, semantic, and procedural memories, plus reinforcement, consolidation, governance, provenance, and inspection. Compartment uses importance and recency ranking and delegates most curation to the host agent.
    
    Engineering-data ingestion: Built-in paths for code, documents, PDF/OCR, audio/video transcription, and PostgreSQL schema ingestion.
    
    Shared-workspace workflows: Optional encrypted workspace sync and hosted team controls, alongside repo and session boundaries. Compartment supports local multi-agent ACLs, but not the same project and team model.
