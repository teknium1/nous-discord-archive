[2026-07-29T11:59:08.303000+00:00] kratos20011 (id=1531994484991201360)
    Expert.md Specification — v1.0
    Status: Open draft, welcoming community feedback.
    Goal: a stable, versioned, testable format so any tool (Hermes, OpenClaw, Claude Code, custom agents) can load, validate, and score an Expert.md file the same way.
    This document defines what a file must contain to be a conformant Expert.md, independent of domain.
    1. Principle
    An Expert.md encodes reflexes, not procedures. It doesn't replace a SKILL.md, it precedes it: always loaded, it triggers the right behavior; the SKILL.md only loads if the agent actually enters technical execution of the domain.
    A conformant file must be:
    Size-bounded: 3–12 KB (beyond that, it's a skill in disguise — see §6)
    Testable: every reflex must be verifiable through a BDD scenario (see bdd/SCHEMA.md)
    Versioned: shipped with a manifest (see §3)
    2. Required section structure
    Section
    Required
    Role
    # EXPERT.md — Domain: [NAME]
    ✅
    Title + domain
    ## ⚠️ Silent prerequisites
    ✅
    Non-negotiable domain assumptions
    ## ⚡ Reflexes
    ✅
    Trigger → action, free prose
    ## 🚫 Anti-patterns
    ✅
    What the agent refuses without discussion
    ## ✅ Quality gates
    ✅
    Checklist before delivery
    ## 🛡️ Typed rules
    Conditional*
    See §4 — required if the domain has an asymmetric cost of omission (security, legal, finance, health)
    ## 📡 Weak signals
    Recommended
    Cases where the agent should stop and ask for confirmation
    *An "asymmetric cost" domain is one where a silent error is catastrophic and unrecoverable after the fact (e.g. data leak, XSS flaw, wrong medical advice). The spec requires the typed section in this case — it's not optional.

    Hello everyone! I have a new update, 1.2.3 (910), which is being uploaded and will soon be available for testing.
    
    The previous version focused primarily on introducing the new design and fixing several issues that could cause sessions to stop or terminate unexpectedly. This update continues to refine that foundation and addresses the main feedback received during the last round of testing.
    
    The session context indicator has returned to the active chat. Tapping it opens a popup window with the token breakdown and available session metrics, including TTFT and cache information when Hermes provides that data.
    
    Cron-generated sessions have also been removed from the regular chat list and moved to their own Cron Results section, so scheduled exits remain accessible without interfering with normal conversations.
    
    Cron and Kanban have been improved to work more like Hermes Desktop, along with adaptive widgets for Android, new light and dark themes, simpler voice setup, and various performance, stability, accessibility, and user interface improvements.
    
    I hope you like the new design; personally, I think it's much cleaner and easier to navigate. Thanks again for all your feedback and support. If you have any issues, please feel free to email me at hola@xpetalab.dev or join me on Discord.
