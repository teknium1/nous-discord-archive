    Yes, I’ve worked with similar agent-based workflows.
    
    For this use case, I’d set up Hermes as the central email agent, with a persistent database for customer, order, supplier, and quote context. The agent would not rely only on email thread IDs, so if a supplier starts a new email thread, it can still match that conversation back to the correct order using the customer, order number, shipment details, supplier, and other identifiers.
    
    The workflow would be
    Customer order → Hermes reads and creates/updates the order record → contacts shipping vendors → handles follow-up questions → collects and compares quotes → updates the order context → prepares the customer confirmation.
    
    For safety, I’d also add an approval step before the final customer confirmation is sent.
    
    The key is separating the agent’s reasoning from the persistent order/customer database, so context is maintained reliably across multiple threads and future conversations.
