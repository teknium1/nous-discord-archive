    I built Hermes Plugin Guard (`hpg`), a local static scanner for Hermes Agent plugins.
    
    It reads target code as data — never imports or executes the plugin — and checks manifests, Python source, dependencies, likely secrets, risky tool/hook behavior, and basic project hygiene before installation.
    
    A community suggestion today led to a new outbound-egress rule (HPG112). It detects common Python HTTP, WebSocket, socket, FTP, SMTP, and gRPC calls, reports only redacted scheme/host/port evidence, and still performs no DNS lookups or scanner network requests.
    
    Five-minute beta test (Python 3.11+):
    ```bash
    pipx install "git+https://github.com/mauricemohr88-debug/hermes-plugin-guard.git@v0.1.1"
    hpg scan /path/to/your/plugin --fail-on none
    ```
    
    GitHub: https://github.com/mauricemohr88-debug/hermes-plugin-guard
    HPG112 PR: https://github.com/mauricemohr88-debug/hermes-plugin-guard/pull/3
    
    I’m looking for a few plugin authors to try it on real projects and tell me which findings are useful, noisy, or missing. Findings are review signals, not claims that a plugin is malicious. The project is unofficial and not affiliated with Nous Research.
