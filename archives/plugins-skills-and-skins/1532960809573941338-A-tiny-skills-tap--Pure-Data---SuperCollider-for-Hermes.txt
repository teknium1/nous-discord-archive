    Two stdlib-only live-audio skills — no MCP, no npm, no compiled bridge, just
    driving a live synth instance over a thin protocol:
    
    🎹 pd-patching   — build & control Pure Data patches over [netreceive]
    🎚️ supercollider — build & control SuperCollider synths over OSC
    
    Install:
      hermes skills tap add mrev-lab/hermes-skills
      hermes skills install mrev-lab/hermes-skills/pd-patching --force
      hermes skills install mrev-lab/hermes-skills/supercollider --force
    
    Repo: https://github.com/mrev-lab/hermes-skills
    
    Why --force? They're community-trust, so the install scanner flags them as
    `caution` (they bind a loopback port by default and mention `sudo` in the setup
    docs). Nothing here touches the network or reads your secrets — `inspect` shows
    the full scan first.
    
    Both are also proposed for the official optional-skills collection (in review):
      pd-patching   → https://github.com/NousResearch/hermes-agent/pull/67456
      supercollider → https://github.com/NousResearch/hermes-agent/pull/67892
    Once merged, install from `official/creative/...` instead and I'll retire them
    from the tap.
