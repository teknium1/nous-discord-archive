    Built another entry for the memory-provider slot and recorded the full install + smoke test. To be clear up front: this runs **alongside** MEMORY.md/USER.md, it doesn't replace them - same as the other providers.
    
    Why bother, given built-in memory is solid: built-in is bounded + local + keyword session search, and it's the agent's own notes. This provider adds the stuff you reach for when that's not enough:
    - a real **knowledge base** — ingests Jira/Confluence/Notion/GitHub/Drive/Slack
    - **hybrid retrieval** — dense + SPLADE + Neo4j graph (built-in session search is FTS keyword)
    - typed records (`fact`/`preference`/`pinned`), team-scoped
    - a **freshness pipeline** for stale/conflicting facts
    
    All self-hosted (Docker + Ollama, no external LLM). Selected the normal way — `hermes config set memory.provider metronix` — nothing exotic.
    
    Straight up: Hermes already ships self-hosted providers (Hindsight, Holographic, OpenViking...). The reason for this one is the unified KB + connectors + freshness combo in one backend, not "self-hosted" on its own. Curious whether that combo is actually what people want or if I'm overbuilding.
